# Arabic PDF Generation Debugging Guide

## Quick Diagnostics

### 1. Check if Puppeteer/PDF Service is Working
Visit: `http://localhost:3000/api/health/pdf`

This endpoint will:
- Test browser launch
- Generate a simple test PDF
- Return detailed error messages if anything fails

**Expected Response:**
- Status 200 with a PDF attachment if working
- Status 500 with detailed error message if broken

---

## Common Issues and Solutions

### Issue 1: Error 500 with "Failed to launch browser"
**Cause:** Chromium is not installed or Puppeteer launch args are incompatible

**Solutions:**
1. Verify Puppeteer is installed: `pnpm list puppeteer`
2. Check if Chromium binary exists
3. In `/lib/html-pdf-generator.ts`, ensure launch args are correct for your environment:
   ```typescript
   args: [
     '--no-sandbox',
     '--disable-setuid-sandbox',
     '--disable-dev-shm-usage',
     '--disable-gpu',
   ]
   ```

### Issue 2: Error with "Failed to generate PDF"
**Cause:** HTML content or rendering issue

**What to check:**
1. The HTML generated by `generateArabicDocumentHTML()` is valid
2. Google Fonts can be loaded (check network in browser dev tools)
3. CSS is properly formatted
4. Check the error details in API response

### Issue 3: Arabic Text Not Rendering
**Cause:** Font issue

**Check:**
1. `generateArabicDocumentHTML()` includes: `<link rel="preconnect" href="https://fonts.googleapis.com">`
2. Font family is set to: `font-family: 'Noto Naskh Arabic', Arial, sans-serif`
3. `dir="rtl"` attribute is on the `<html>` tag

## Debug Logging Output

When generating an Arabic PDF, you should see these logs (in order):

1. **Request Received:**
   ```
   [v0] Recommendation request body: { studentId: "...", programId: "...", type: "recommendation", language: "ar" }
   ```

2. **Student Data Fetched:**
   ```
   [v0] Student data fetched successfully
   [v0] Program data fetched successfully
   ```

3. **HTML Generation:**
   ```
   [v0] Generating Arabic document HTML...
   [v0] Arabic HTML generated successfully, length: 5420
   ```

4. **PDF Generation:**
   ```
   [v0] Starting PDF generation from HTML...
   [v0] PDF generated successfully, size: 45678 bytes
   ```

5. **Database Update:**
   ```
   [v0] Recommendation recorded in database
   ```

**If any step is missing,** the error occurred at that point. Check the error message that follows.

## Puppeteer Configuration

The current configuration in `/lib/html-pdf-generator.ts`:

```typescript
puppeteer.launch({
  headless: 'new',
  args: [
    '--no-sandbox',           // Required for Docker/server environments
    '--disable-setuid-sandbox',  // Required for server environments
    '--disable-dev-shm-usage',   // Prevents memory issues in containers
    '--disable-gpu',          // Disables GPU acceleration (not needed for headless)
  ],
})
```

These are optimized for server environments. If you're running locally and getting issues, try:
```typescript
puppeteer.launch({
  headless: true,
  // Remove the args array for local development
})
```

## Browser Instance Reuse

The system reuses a single browser instance for efficiency:

```typescript
let browserInstance: Browser | null = null

async function getBrowser(): Promise<Browser> {
  if (browserInstance) {
    return browserInstance  // Reuse existing instance
  }
  // Launch new browser
}
```

This means:
- First PDF generation is slower (browser startup)
- Subsequent requests are faster
- If browser crashes, next request will restart it

## Performance Notes

**Expected Timings:**
- First Arabic PDF: 2-5 seconds (browser startup)
- Subsequent PDFs: 500-1500ms (depends on HTML complexity)
- English PDFs (jsPDF): 50-200ms (instant)

**If timing is much slower:**
1. Check if Puppeteer is launching multiple browser instances
2. Monitor memory usage (Chromium can use 100-300MB)
3. Check network for Google Fonts delays

## Next Steps if Still Getting 500 Error

1. **Check the `/api/health/pdf` endpoint first** - confirms service is working
2. **Review the error details** - look for "Failed to launch browser" vs "Failed to generate PDF"
3. **Check server logs** - all debug messages go to console
4. **Verify database connection** - ensure admin client is working (it fetches student data first)
5. **Test with English language first** - verify the basic route works before testing Arabic
6. **Check Chrome/Chromium availability** - `which chromium` or `which google-chrome`
